CRAFTED MEDIA WEBSITE
CODEX PHASED DEVELOPMENT & APPROVAL PLAN
=========================================

Purpose
-------
Build the Crafted Media Photography & Cinematography website incrementally.

The website should feel premium, cinematic, artistic, modern and warm, using a
Peacock Blue + Cream/Ivory visual identity. Photography and films must remain
the primary visual focus.

The website is not only a portfolio. It must ultimately work as a premium
lead-generation website while remaining fast, mobile-first, easy to maintain,
SEO-friendly and capable of supporting 500+ portfolio images.

IMPORTANT DEVELOPMENT RULE
--------------------------
Codex MUST complete ONLY ONE PHASE at a time.

For every phase Codex must:

1. Read this complete plan before making changes.
2. Check the CURRENT PROJECT STATUS section.
3. Work ONLY on the active phase.
4. Do not begin any later phase even if it appears easy or related.
5. Preserve all features completed in earlier approved phases.
6. Run the required tests for the phase.
7. Fix all issues found by those tests.
8. Perform regression checks on important functionality from earlier phases.
9. Update this TXT file before finishing the phase.
10. Mark the phase as:
       READY FOR USER REVIEW
   but NOT:
       APPROVED
11. Stop and ask the user to review/test the phase.
12. Continue to the next phase ONLY after the user explicitly approves the
    current phase.

If the user requests changes during review:
- keep the phase status as IN REVIEW,
- implement the requested changes,
- rerun tests,
- update this document,
- return it for review again.

Never self-approve a phase.


======================================================================
RECOMMENDED DEVELOPMENT PRINCIPLES
======================================================================

1. Mobile-first development.
2. Progressive enhancement instead of building everything at once.
3. Reusable components instead of duplicated page code.
4. Portfolio categories/albums must be data-driven and NOT hard-coded into
   individual pages.
5. Architecture must support adding future portfolio categories without
   redesigning the website.
6. Optimize for hundreds of photographs but curate a much smaller number on
   public-facing pages.
7. Prefer large editorial photography layouts over dense image grids.
8. Keep animations subtle.
9. Avoid adding heavy frameworks/libraries unless justified.
10. Keep the public website functional even if optional integrations fail.
11. Never commit secrets/API keys.
12. Maintain accessibility basics:
    semantic HTML, keyboard navigation, labels, alt text, visible focus states
    and sufficient contrast.
13. Do not host large cinematography files directly unless specifically
    required. Prefer YouTube/Instagram/Vimeo style embeds or links.
14. Every phase should leave the repository in a deployable state.

FINAL PRODUCT PRINCIPLE
======================================================================

The website must never compete with the photographs.

Avoid:
- excessive animation,
- overly colourful backgrounds,
- complicated UI,
- clutter,
- giant blocks of text,
- unnecessary effects.

Desired visitor reaction:

"Wow. I want my photos to look like this."

The experience should naturally guide a visitor through:

Emotion
-> Portfolio
-> Story
-> Trust
-> Availability
-> Enquiry
-> WhatsApp conversation
